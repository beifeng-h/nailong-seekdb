## 2. 红线（违反了就是错，不是"风格问题"）

1. **不预存答案。** 题包原话："请实现正常执行与错误处理，而非预存样例答案。"
   禁止按用例 id、表名、行数做特判；禁止把 `.result` 抄进代码或数据文件。
2. **不拿公开用例替代正式用例。** 基础样例已简化，不能用评测仓库中的同名
   正式用例替代题包目录里的实际文件；公开用例里没有覆盖的功能要求
   （非法向量、崩溃恢复、资源上限、ANN 召回）**照样要实现**。
3. **不泄露。** 仓库、日志、协议报文里不放密钥、凭据、账号、内网地址。
   stdout 只允许出现协议报文。
4. **不假装。** 没跑过的命令不写进结论；失败了就贴失败输出，不改写。

## 3. 协议硬约束（照抄 `STDIO_PROTOCOL.md`，不自己发明）

- **启动握手**：程序启动后、完成恢复之后，**主动**输出一行
  `{"type":"ready"}` 并 flush。必须在等待第一条请求之前输出。
  `READY`、`{"ready":true}`、`{"status":"ready"}` 全部非法。
- **一行一报文**：每个报文占一个物理行；字符串里的换行由 JSON 序列化器
  转义；输出后立即 flush；不输出空行、提示符、代码围栏、ANSI 颜色、
  多余状态行。
- **请求**：一行一个 JSON。`op` 取 `execute` 或 `shutdown`；
  `execute` 带 `sql` 和 `search_mode`（`exact` / `ann`）。
  **不要把整行 JSON 当 SQL，也不要用分号切原始输入**——分号可能出现在
  SQL 字符串内部。
- **响应**：每个请求恰好一个响应，**原样回传请求 `id`（含它的 JSON 类型，
  数字不能变字符串）**，并且 `ok` 必须是 JSON 布尔值。
  - 查询成功：`{"id":n,"ok":true,"columns":[...],"rows":[[...],...]}`，
    空结果集仍要返回列名，`rows` 为空数组；
  - 增删改成功：`{"id":n,"ok":true,"affected_rows":n}`；
  - 建表与事务控制语句：至少含 `id` 和 `ok:true`；
  - 失败：`{"id":n,"ok":false,"error":{"code":"<非空字符串>","message":"..."}}`，
    判题不依赖 `message` 措辞。
- **预期中的 SQL 错误不终止进程**：发失败响应后继续接收下一条请求。
- **关闭**：`{"id":n,"op":"shutdown"}` → 回滚未提交事务 → 落盘 → 返回
  `{"id":n,"ok":true}` → flush → **之后 stdout 不得再有任何输出**
  （连空行都不行）→ 退出码 0。
- **数据类型**：BIGINT 走 JSON 整数，不能转字符串、不能经浮点丢精度；
  NULL 用 JSON `null`；向量投影用 JSON 数组，浮点必须是有限值；
  不输出 NaN / Infinity，不使用重复对象键。
- **启动参数**：Dockerfile 的默认入口就是上面这套 stdin/stdout 模式，
  不能默认进 SQL 提示符、不能默认起网络服务、不能依赖判题器补传私有参数。

## 4. 语义硬约束（来自题包「正式验收要求仍然公开」）

1. **先过滤，再 TopK。** 带 `WHERE` 的向量查询必须先在满足条件的集合里
   排序再取 TopK，而不是"先取 TopK 再过滤"。
   *反例*：库里存在 A 类记录，全表最近的一条是 B 类。"先全表取 Top1
   再过滤"会得到空结果，"先过滤再取 Top1"才正确。
2. **并列按主键升序。** 距离相同的行，按 `id` 升序稳定输出。
3. **float32 存储、float64 计算。** 向量按 float32 存；距离按 float64 算；
   `L2_DISTANCE` 返回**欧氏距离**而不是距离平方（`[3,4]` 与 `[0,0]` 的
   距离是 5，不是 25）。
4. **拒绝非法向量。** NaN、Infinity、维度错误、float32 溢出都必须报错。
5. **失败语句不能部分生效。** 一条语句里任何一行出错，整条语句的行级
   改动全部撤销；显式事务中该语句**之前**的成功修改仍可提交或回滚。
6. **崩溃恢复。** 已确认提交在进程被强杀后仍然保留；未提交修改不部分
   生效；恢复途中再次退出仍能恢复。持久性不能依赖"正常关闭时才落盘"。
7. **不能只依赖全量常驻内存。** 在 32 MiB 地址空间上限下也要能处理
   超过内存限额的数据。
8. **ANN 的四条。** 满足过滤、有效 ID、无重复、题包规定的召回率；
   索引更新不能破坏事务语义。

## 5. 验证纪律

### 5.1 独立真值，不是自证

判据必须来自**独立于被测实现**的真值：解析出的参考实现、手算的期望值、
或组织方题包里的断言。用实现自己的输出给自己作证不算验证。

浮点比较用绝对/相对容差 `1e-5`（与 `protocol_check/config.json` 一致）；
整数与字符串精确比较；`unordered` 查询用多重集合比较，重复行不能丢。

### 5.2 每条结论带证据

结论的最小形式是：**命令 + 真实输出 + 出处**（提交号、CI 运行链接、
文件路径）。没有输出就不算验证过。

### 5.3 公开用例通过 ≠ 正式准入

自测工具的 `result.json` 里 `passed=true` 只说明**本次选中的检查**通过。
题包原文："握手通过不代表 SQL 正确；公开用例通过不代表正式 29 个用例或
性能/Agent 评审通过。" 不要在结论里把这两件事混为一谈。

### 5.4 失败先定位，再改

遇到失败，先给出**它属于哪一类**（协议/语义/持久化/资源），再动手。
一次改一个变量，改完立刻重跑最小复现，再跑全量。

## 6. 工作方式

1. **一次一个可验证的增量。** 每个增量都能被一条命令验证；验证不过不往下走。
2. **最小复现优先。** 复杂失败先缩到一个用例、一条 SQL。
3. **用组织方的工具验证。** 题包自带的 `protocol_check/run.py` 是判题语义的
   复刻，优先用它，而不是自己写一个"差不多"的脚本。
4. **CI 是唯一可信的环境。** 容器行为（默认入口、只读根文件系统、
   `/data` 挂载、无网络）只能在 CI 的 Linux 容器里验证；本地结论不能
   替代容器结论。
5. **不确定就说不确定。** 明确区分"已验证""推断""待验证"，不要用肯定语气
   描述没有证据的部分。
